# EcoBio-Matrix · المرحلة 3: قاعدة بيانات Supabase

قاعدة بيانات مجانية على Supabase، فيها جدولين:
- `sensor_readings`: قراءات الـ ESP32.
- `events`: أحداث الحماية.

المفتاح العام يقدر يضيف ويقرأ بس، وما يقدر يعدّل ولا يحذف. الجدولين مفعّل لهم Realtime عشان لوحة المرحلة 4 تتحدث لحالها.

## الملفات

| الملف | وش فيه |
|---|---|
| `schema.sql` | الكود اللي تلصقه: الجدولين، والصلاحيات (RLS)، والفهارس، وRealtime |
| `verify.sql` | فحص سريع بعد التشغيل، والمفروض كل الصفوف `true` |
| `tools/test_schema.mjs` | الاختبار اللي سويته على Postgres حقيقي في جهازي (35 فحص) |
| `tools/test_rest.ps1` | يفحص مشروعك الحقيقي من برّا بالمفتاح العام |

## الخطوات (تقريبًا 10 دقايق)

### 1) سوّ المشروع المجاني
1. ادخل [supabase.com](https://supabase.com) واضغط **Start your project**، وسجّل بحساب GitHub أو إيميل.
2. اضغط **New project** واعبّي التالي:
   - **Organization:** اللي يطلع لك، على الخطة المجانية (Free).
   - **Project name:** `ecobio-matrix`
   - **Database password:** اضغط Generate واحفظها عندك. ما نحتاجها في الربط، و**لا ترسلها لأحد**.
   - **Region:** أقرب منطقة تطلع لك في القائمة.
   - لو طلع لك خيار **Data API**، خلّه مفعّل. البرنامج واللوحة يكلمون القاعدة من خلاله.
3. اضغط **Create new project** وانتظر لين تخلص التجهيز.

### 2) الصق الكود
1. من القائمة اليسار افتح **SQL Editor**.
2. اضغط **New query** (علامة +).
3. الصق محتوى `schema.sql` كامل، واضغط **Run** أو Ctrl+Enter.
4. لو طلع تحذير إن الكود فيه أوامر «خطيرة»، اضغط **Run this query**. التحذير يطلع بسبب سطور `drop policy if exists` و `revoke`، وهي ما تمسح أي بيانات.
5. المفروض تطلع: `Success. No rows returned`.

### 3) افحص
1. سوّ **New query** ثانية، والصق `verify.sql`، واضغط **Run**.
2. لازم تطلع **12 صف كلها `ok = true`**:
   - الجدولين موجودين.
   - RLS مفعّل.
   - المفتاح العام يقرأ ويضيف بس.
   - الفهارس موجودة.
   - Realtime مفعّل.

### 4) الرابط والمفتاح
- **الأسهل:** اضغط زر **Connect** فوق في صفحة المشروع. يطلع لك:
  - **Project URL**، وشكله `https://xxxx.supabase.co`
  - **Publishable key**، وشكله `sb_publishable_...`
- **أو:** من ⚙️ **Settings** ← **API Keys**. لو لقيت تبويب **Legacy API keys** فيه مفتاح **anon** يبدأ بـ `eyJ`، البرنامج يقبله بعد.
- **لا تستخدم ولا ترسل لأحد:**
  - **Secret key** (`sb_secret_...`)
  - **service_role**
  - كلمة سر قاعدة البيانات

  هذي تتجاوز كل الحماية.

### 5) فحص من الجهاز (اختياري)
في PowerShell داخل مجلد `tools`:
```
powershell -ExecutionPolicy Bypass -File test_rest.ps1 -Url https://xxxx.supabase.co -Key sb_publishable_xxxx
```
المفروض يطلع `7 passed, 0 failed`. يعني: إضافة قراءة وحدث نجحت، وقراءتهم رجعت، والتعديل والحذف انرفضوا.

### 6) اربط Wokwi
1. في مشروع Wokwi، استبدل `sketch.ino` كامل بالنسخة الجديدة من `esp32-wokwi/sketch.ino`. فيها تعديل صغير عشان المفتاح الجديد (شوف تحت).
2. غيّر السطرين في أعلى الملف بالرابط والمفتاح:
   ```cpp
   const char* SUPABASE_URL      = "https://xxxx.supabase.co";
   const char* SUPABASE_ANON_KEY = "sb_publishable_xxxx";
   ```
3. اضغط **SAVE**، وبعدها ▶، وخلّ التبويب ظاهر قدامك.
4. في Serial لازم يتغيّر `Supabase not set` ويصير `net: online, sent N, waiting 0`، والرقم N يزيد.
5. في Supabase افتح **Table Editor**: المفروض تشوف `sensor_readings` تزيد كل ثانية، و `events` فيها `boot` وبعده `restore`.

لو طلع في Serial سطر يبدأ بـ `[NET] sensor_readings: HTTP` ومعه رقم مثل 401 أو 404، انسخه وأرسله لي.

## شكل الجدولين

**`sensor_readings`**: أسماء الأعمدة نفس اللي يرسلها `sketch.ino` بالضبط.

| العمود | النوع | المعنى |
|---|---|---|
| `id` | رقم تلقائي | ما يقدر أحد يحدده من برّا |
| `ts` | وقت UTC | وقت القراءة الأصلي. لو ما انرسل، ينحط وقت الوصول |
| `ph` | رقم | من 0 إلى 14، أو `null` لو الحساس معطل |
| `orp_in_mv` | رقم | ORP1 بالـ mV |
| `do_mgl` | رقم | الأكسجين المذاب (mg/L)، 0 أو أكثر |
| `temp_c` | رقم | الحرارة (°C) |
| `turbidity` | رقم | العكارة (NTU)، 0 أو أكثر |
| `uv_pct` | رقم | شدة UV، من 0 إلى 100 |
| `orp_cl_mv` | رقم | ORP2 بالـ mV |
| `level_pct` | رقم | امتلاء التخزين، من 0 إلى 100 |
| `valve1`، `valve2` | نص | `normal` أو `sewer` بس |
| `air_pump`، `cl_pump`، `safe_mode` | صح/خطأ | |

**`events`**:

| العمود | النوع | المعنى |
|---|---|---|
| `id` | رقم تلقائي | |
| `ts` | وقت UTC | وقت الحدث |
| `type` | نص | حروف إنجليزية صغيرة و `_` بس، مثل `boot` و `divert` و `restore` و `safe_mode` و `net_offline` |
| `reason` | نص | السبب بالعربي، 500 حرف كحد أعلى |
| `valve` | نص | `valve1` أو `valve2` أو `both` أو فاضي |
| `value` | رقم | القراءة اللي سببت الحدث |
| `decided_by` | نص | `rule` أو `ai` بس، والافتراضي `rule` |

الحدود اللي فوق (pH من 0 إلى 14، والنسب من 0 إلى 100) **حدود فيزيائية بس، مو حدود التشغيل**. حدود التشغيل مثل 6.5 إلى 8.4 موجودة في الـ ESP32. القاعدة تحتاج هالحدود لأن المفتاح العام مكشوف، وأي أحد يقدر يرسل قيم مستحيلة.

## ليش المفتاح العام آمن هنا؟
- المفتاح العام (publishable أو anon) يشتغل بدور اسمه `anon`. أعطيناه صلاحيتين بس: **إضافة وقراءة**.
- الحماية في طبقتين:
  - **RLS:** فيه سياستين بس، وحدة للإضافة ووحدة للقراءة. ما فيه سياسة تعديل ولا حذف.
  - **GRANT:** سحبنا صلاحية التعديل والحذف والتفريغ من الأساس.
- يعني حتى لو أحد أخذ المفتاح من Wokwi أو من اللوحة، ما يقدر يمسح أو يغيّر أي قراءة. أقصى شي يقدر يسويه إنه يضيف صفوف. وحدود الأعمدة ترفض القيم المستحيلة، بس ما تمنع صفوف وهمية بقيم معقولة.

## مسح بيانات التجارب (قبل العرض)
المفتاح العام ما يقدر يمسح. أنت تمسح من **SQL Editor**، لأن حسابك صاحب القاعدة:
```sql
-- صفوف فحص test_rest.ps1 بس
delete from public.sensor_readings where ts < '2001-01-01';
delete from public.events where type = 'connection_test';

-- أو كل شي (يصفّر الجدولين ويرجّع العداد من 1)
truncate public.sensor_readings, public.events restart identity;
```

**اللي ما تأكد بعد:**
- ما جرّبته على Supabase نفسه، لأنه يحتاج حساب ومشروع باسمك.
- الإرسال الفعلي من Wokwi لـ Supabase **تأكد** (20 نوفمبر): القراءات والأحداث وصلت للمشروع الحقيقي بالمفتاح الجديد `sb_publishable_`، بوقتها الأصلي والعربي سليم. وانقطاع أول محاولة اتعالج بإعادة المحاولة بدون ما تضيع ولا قراءة.
- `verify.sql` على المشروع الحقيقي **تأكد** (20 نوفمبر): 12 من 12 `true`. يعني الجدولين موجودين، وRLS مفعّل، وانرفع لـ anon صلاحيتين بس (SELECT و INSERT)، وما فيه سياسة تعديل ولا حذف، والفهارس موجودة، وRealtime مفعّل للجدولين.
- محاولة تعديل أو حذف فعلية عبر الإنترنت على المشروع الحقيقي بالمفتاح العام **تأكدت** في المرحلة 4 (20 نوفمبر): الاثنين رجعوا `401` مع `42501 permission denied`. وRealtime يوصل الصف الجديد خلال قرابة 0.1 ثانية.

الاثنين يتأكدون بالخطوة 5 والخطوة 6 فوق.

## ملاحظات مهمة

1. **مشاريع الخطة المجانية توقف لو ما فيها نشاط كافي لمدة أسبوع**، حسب [توثيق Supabase](https://supabase.com/docs/guides/platform/free-project-pausing). العرض يوم 5 ديسمبر، فالأفضل:
   - شغّل محاكاة Wokwi كم دقيقة كل كم يوم، أو على الأقل في الأسبوع اللي قبل العرض.
   - افتح لوحة Supabase اليوم اللي قبل العرض وتأكد إن المشروع **مو Paused**. لو صار Paused، فيه زر Restore بس يأخذ وقت.
2. **المفتاح الجديد ما ينرسل كـ Bearer.** حسب [توثيق مفاتيح Supabase](https://supabase.com/docs/guides/getting-started/api-keys)، مفتاح `sb_publishable_` مو JWT، ومكانه ترويسة `apikey`. عشان كذا عدّلت `sketch.ino`: يرسل `Authorization` بس لو المفتاح القديم (`eyJ...`). نفس القاعدة مطبقة في `test_rest.ps1`، وبتنطبق في لوحة المرحلة 4.
3. **مفاتيح anon و service_role القديمة** Supabase يوقفها مع نهاية 2026 حسب نفس التوثيق، فالأفضل نستخدم الجديد `sb_publishable_`.
4. **Realtime بالمفتاح العام:** الاتصال العام يستمر 24 ساعة كحد أعلى حسب التوثيق، ويكفي للعرض. التجربة الفعلية تكون في المرحلة 4.
